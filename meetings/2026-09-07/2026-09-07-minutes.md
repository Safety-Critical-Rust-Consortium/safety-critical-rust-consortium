## Unconf

### Unsafe Rust (technical perspective, safety)

* **[Jeongsoo]** To transcribe notes from his notebook
* Sound vs unsound is one distinction
  * But there may be further distinctions than those two
* In C, UB means "not defined in the standard"; in Rust, UB means "something else"
* Variable in C: if filled with garbage it becomes UB at read time
* Variable in Rust: if filled with garbage it is UB at definition
  * Raw pointer into a C object filled with garbage
* Some discussion of volatility
  * In C, related to a piece of data
  * In Rust, a property of accessing the data (e.g. in a volatile manner, read or write)

#### Unsafe APIs

* Missed understanding for some in the discussion: API of core/std library is committed (RFC 1105, i.e. semver is applied to the standard library)
* Difference between "committed Rust library APIs" vs not being the case in other languages
* Not a "transfer concepts exercise", but one that's about how to build up the understanding within Rust

### White Paper for cert process from C, C++ => Rust

* **Audience:** people who have experience certifying or qualifying with C and C++
* **Objective:** make people realize that Safety Certification with Rust is Possible Now
* **[Orson]** MVP: Copy-paste this into an issue on GitHub so that we do not forget that we wish to do these things

**Section 1:**

* What is the difference between Rust and C from a certification basis?
* Message: the process is essentially the same; must prove that our software is doing exactly what it is supposed to do
* Process overview: what is carried over? And what can be cut
  * Requirements, activities, evidence (test coverage); with Rust, process is cut down because a bunch of safety objectives are met "de facto"
  * Can reference existing ISO 26262 gap analysis for Rust: https://arewesafetycriticalyet.org/docs/iso26262

**Section 2:**

* Gap analysis of Rust tooling ecosystem vs C
* What we're missing AND what we don't need (what the compiler does that C doesn't do)
* See tooling content on the safety website: https://arewesafetycriticalyet.org/tooling/tools-list

**Section 3:**

* Pure Rust projects vs mixed Rust/C projects

* Vertical market standards coverage & gap analysis
